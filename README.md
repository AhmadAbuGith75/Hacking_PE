## إخلاء المسؤولية

هذا المستند مخصص للأغراض التعليمية وتقييم الأمن المعتمد فقط. يجب استخدام التقنيات والأوامر المذكورة هنا في بيئات تملك تصريحا واضحا لاختبارها.

يجب إجراء أي اختبار أمني فقط:

* بإذن خطي من مسؤول الشبكة
* ضمن بيئة اختبار مصرح بها
* لأغراض تعليمية في بيئة محكومة
* بهدف اكتشاف المشاكل الأمنية ومعالجتها

الوصول غير المصرح به إلى أنظمة الحاسوب غير قانوني.

## الملخص التنفيذي

يهدف هذا التقرير إلى توثيق مجموعة من الأوامر والأدوات التي يمكن استخدامها أثناء تقييم أمني معتمد لشبكة مختبر.

يركز التقييم على اكتشاف بعض التكوينات التي قد تزيد من احتمالية الحركة الجانبية داخل الشبكة، مثل:

* إمكانية الاتصال المباشر بين محطات العمل
* مشاركة الملفات عبر SMB
* إعدادات Network Discovery
* استخدام بيانات اعتماد مشتركة
* الخدمات المكشوفة بين أجهزة الشبكة

جميع الاختبارات المذكورة هنا تعتمد على عمليات اكتشاف وفحص يمكن استخدامها ضمن بيئة اختبار مصرح بها.

## أوامر اكتشاف الشبكة

### 1. أوامر Windows CMD

#### 1.1 عرض الأجهزة التي تم اكتشافها محليا

```cmd
arp -a
```

يعرض هذا الأمر ذاكرة ARP الموجودة على الجهاز، والتي تحتوي على معلومات عن الأجهزة التي تم التواصل معها مؤخرا على الشبكة المحلية.

الأمر للقراءة فقط ولا يقوم بتغيير إعدادات الشبكة.

---

#### 1.2 اختبار الاتصال

```cmd
ping <IP_ADDRESS>
```

مثال:

```cmd
ping 10.8.20.15
```

يستخدم الأمر لاختبار إمكانية الوصول إلى جهاز آخر على الشبكة.

إذا نجح الاتصال فهذا يعني أن الجهاز الحالي يستطيع الوصول إلى العنوان المستهدف باستخدام ICMP، مع ملاحظة أن بعض الأجهزة قد تمنع ICMP من خلال جدار الحماية.

---

#### 1.3 التحقق من مشاركات SMB

```cmd
net view \\<IP_ADDRESS>
```

مثال:

```cmd
net view \\10.8.20.15
```

يمكن استخدام الأمر للتحقق من الموارد المشتركة التي يمكن للجهاز الحالي رؤيتها على الجهاز المستهدف.

مثال على مخرجات محتملة:

```text
Shared resources at \\10.8.20.15

Share name  Type  Used as  Comment
-----------------------------------------
Public      Disk
IPC$        IPC
```

ظهور مشاركة لا يعني بالضرورة وجود ثغرة. يجب التحقق من الأذونات ونوع البيانات التي يمكن الوصول إليها.

---

#### 1.4 عرض الأجهزة الظاهرة في Network Browsing

```cmd
net view
```

يعرض الأجهزة التي يمكن اكتشافها من خلال آليات استعراض الشبكة المتوفرة في البيئة.

## تحليل PowerShell

### 2.1 اكتشاف جيران الشبكة

```powershell
Get-NetNeighbor
```

يعرض معلومات الجيران المعروفة لواجهة الشبكة، وهو بديل حديث نسبيا لعرض معلومات ARP.

---

### 2.2 اختبار منفذ SMB

```powershell
Test-NetConnection -ComputerName <IP_ADDRESS> -Port 445
```

مثال:

```powershell
Test-NetConnection -ComputerName 10.8.20.15 -Port 445
```

أهم نتيجة هي:

```text
TcpTestSucceeded: True
```

إذا كانت `True` فهذا يعني أن الاتصال عبر TCP إلى المنفذ 445 ممكن من الجهاز الحالي.

أما `False` فتعني أن الاتصال لم ينجح، وقد يكون السبب جدار الحماية أو عدم تشغيل الخدمة أو عدم وجود مسار للشبكة.

---

### 2.3 الوصول إلى معلومات مشاركات SMB

```powershell
Get-SmbShare -CimSession <IP_ADDRESS>
```

مثال:

```powershell
Get-SmbShare -CimSession 10.8.20.15
```

يعتمد نجاح الأمر على الأذونات المتوفرة على الجهاز المستهدف.

---

### 2.4 مراجعة قواعد Network Discovery

```powershell
Get-NetFirewallRule -DisplayGroup "Network Discovery"
```

يستخدم الأمر لعرض قواعد جدار حماية Windows المرتبطة بـ Network Discovery.

وجود Network Discovery مفعلا ليس ثغرة بحد ذاته، ولكن في بعض البيئات قد يكون من الأفضل تقييد الاكتشاف والاتصالات بين محطات العمل.

## أدوات الأمان

### 3.1 Nmap

يمكن استخدام Nmap أثناء التقييمات المصرح بها لاكتشاف الخدمات والمنافذ المتاحة.

مثال:

```bash
nmap -sT <IP_ADDRESS>
```

يساعد الفحص في معرفة المنافذ التي يمكن الوصول إليها من الجهاز الحالي، مثل:

```text
445  SMB
3389 RDP
80   HTTP
443  HTTPS
```

يجب استخدام Nmap فقط ضمن نطاق اختبار مصرح به.

---

### 3.2 Advanced IP Scanner

يمكن استخدام Advanced IP Scanner لاكتشاف الأجهزة الموجودة على الشبكة من خلال واجهة رسومية.

من الوظائف المتوفرة:

* اكتشاف الأجهزة
* عرض عناوين IP و MAC
* التعرف على بعض الخدمات
* عرض بعض الموارد المشتركة

الموقع الرسمي:

https://www.advanced-ip-scanner.com/

---

### 3.3 Fing Desktop

يوفر Fing Desktop واجهة رسومية لاكتشاف الأجهزة الموجودة على الشبكة وعرض معلومات مثل:

* اسم الجهاز
* عنوان IP
* عنوان MAC
* بعض الخدمات المكتشفة

يمكن استخدامه للمساعدة في توثيق بيئة المختبر.

## أدوات الفحص التلقائي

تم توفير سكربتات بسيطة للمساعدة في جمع معلومات الشبكة ضمن بيئة الاختبار.

### PowerShell

الموقع:

```text
scripts/network-scanner.ps1
```

يقوم السكربت بجمع بعض المعلومات مثل:

* معلومات الجهاز المحلي
* نظام التشغيل
* عناوين IP
* الأجهزة التي يمكن اكتشافها
* بعض المنافذ الشائعة
* معلومات SMB المتاحة
* حفظ النتائج بصيغة JSON

طريقة التشغيل:

```powershell
cd scripts
.\network-scanner.ps1
```

إذا كانت هناك مشكلة في Execution Policy:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
.\network-scanner.ps1
```

السكربت مكتوب باللغة الإنجليزية لتجنب مشاكل الترميز في PowerShell.

مثال على المخرجات:

```text
Network Security Scanner Tool
Educational Purposes Only

Gathering local network information...

=== Local Device Information ===
Hostname: LAB-PC01
Operating System: Microsoft Windows 11 Pro
Version: 10.0.22621
Architecture: 64-bit

IP Addresses:

InterfaceName    IPv4Address      SubnetMask
-------------    -----------      ----------
Ethernet         192.168.1.100    24

Scanning network devices...

Number of devices: 5
```

---

### Bash

الموقع:

```text
scripts/network-scanner.sh
```

يمكن استخدام السكربت على Linux و macOS لجمع معلومات الشبكة وفحص بعض الخدمات.

التشغيل:

```bash
chmod +x scripts/network-scanner.sh
cd scripts
./network-scanner.sh
```

يمكن استخدام صلاحيات root عند الحاجة إلى ميزات تتطلب صلاحيات أعلى:

```bash
sudo ./network-scanner.sh
```

المتطلبات الاختيارية:

```bash
sudo apt-get install nmap arp-scan smbclient
```

لأنظمة Fedora و RHEL:

```bash
sudo dnf install nmap arp-scan samba-client
```

## حالات الاستخدام التعليمية

### فحص شبكة المختبر

```powershell
.\network-scanner.ps1
```

يمكن للسكربت جمع المعلومات الأساسية عن الجهاز والشبكة وحفظ النتائج.

### فحص جهاز محدد

يمكن إدخال عنوان IP للجهاز المطلوب تقييمه ضمن نطاق المختبر.

مثال:

```text
192.168.1.15
```

### توثيق النتائج

يفضل حفظ نتائج الاختبارات مع:

* التاريخ والوقت
* عنوان الجهاز الذي تم الفحص منه
* عنوان الجهاز المستهدف
* الأوامر المستخدمة
* النتائج
* الملاحظات والتوصيات

## منهجية تقييم الثغرات

### المرحلة الأولى: تقييم رؤية الشبكة

الهدف هو معرفة ما إذا كانت محطات العمل قادرة على اكتشاف بعضها والتواصل معها.

الأوامر المستخدمة:

```cmd
arp -a
```

```cmd
ping <TARGET_IP>
```

يجب تفسير النتائج ضمن تصميم الشبكة وسياسات العزل الموجودة.

---

### المرحلة الثانية: تحليل الخدمات المكشوفة

الهدف هو معرفة الخدمات التي يمكن الوصول إليها من محطة عمل إلى أخرى.

مثال:

```powershell
Test-NetConnection -ComputerName <TARGET_IP> -Port 445
```

يمكن استخدام Nmap أيضا ضمن نطاق الاختبار:

```bash
nmap -sT <TARGET_IP>
```

وجود منفذ مفتوح لا يعني وجود ثغرة بحد ذاته، وإنما يحتاج إلى مراجعة الخدمة وإعداداتها وصلاحيات الوصول إليها.

---

### المرحلة الثالثة: مراجعة مشاركات SMB

يمكن التحقق من المشاركات المتاحة باستخدام:

```cmd
net view \\<TARGET_IP>
```

أو:

```powershell
Get-SmbShare -CimSession <TARGET_IP>
```

يجب التحقق من أذونات كل مشاركة ونوع البيانات الموجودة فيها.

---

### المرحلة الرابعة: مراجعة المصادقة

من النقاط التي يمكن مراجعتها في بيئة المختبر:

* استخدام كلمات مرور موحدة
* مشاركة بيانات اعتماد الحسابات
* وجود حسابات مسؤول محلية متشابهة
* عدم وجود تقسيم مناسب بين محطات العمل
* إمكانية استخدام بيانات اعتماد جهاز في جهاز آخر

استخدام بيانات اعتماد مشتركة بين عدة أجهزة يزيد من أثر اختراق أي حساب ويجعل الحركة الجانبية أسهل.

## النتائج والتوصيات

### النتائج المحتملة

| النتيجة                           | مستوى الخطورة | التأثير المحتمل                                   |
| --------------------------------- | ------------- | ------------------------------------------------- |
| الوصول غير المقيد بين محطات العمل | عالي          | زيادة إمكانية الحركة الجانبية                     |
| مشاركات SMB غير مقيدة             | عالي          | إمكانية الوصول إلى ملفات وموارد غير مصرح بها      |
| بيانات اعتماد مشتركة              | حرج           | إمكانية استخدام نفس بيانات الاعتماد على عدة أجهزة |

يجب تحديد مستوى الخطورة النهائي بناء على نتائج الاختبار الفعلية وتأثير كل مشكلة على البيئة.

## التوصيات

### 1. تقسيم الشبكة

استخدام VLANs وسياسات Firewall لعزل محطات العمل وتقليل الاتصالات غير الضرورية بينها.

يمكن تقييد الوصول إلى خدمات مثل:

```text
SMB  445
RDP  3389
```

بحيث تكون متاحة فقط للأجهزة التي تحتاج إليها.

---

### 2. مراجعة Network Discovery

يمكن تعطيل قواعد Network Discovery في البيئات التي لا تحتاج إليها:

```powershell
Set-NetFirewallRule -DisplayGroup "Network Discovery" -Enabled False
```

يجب اختبار تأثير هذا التغيير قبل تطبيقه على أجهزة الإنتاج.

---

### 3. استخدام بيانات اعتماد فريدة

يفضل أن يكون لكل جهاز حساب مسؤول محلي بكلمة مرور فريدة.

يمكن استخدام Microsoft LAPS لإدارة كلمات مرور الحسابات المحلية بشكل مركزي.

---

### 4. تقوية SMB

يجب تعطيل SMBv1 في الأنظمة التي لا تحتاج إليه، والاعتماد على الإصدارات الحديثة من SMB.

يمكن مراجعة إعدادات SMB من خلال أدوات Windows الإدارية بدلا من الاعتماد على أوامر قد تختلف حسب إصدار النظام.

---

### 5. المراقبة والتسجيل

من المفيد تفعيل ومراجعة سجلات الوصول ومحاولات المصادقة ومراقبة الأنشطة غير المعتادة بين محطات العمل.

في البيئات الكبيرة يمكن استخدام SIEM لجمع وتحليل هذه السجلات.

عند تقديم نتائج التقييم للإدارة أو مسؤول الشبكة، يفضل عرض كل مشكلة بهذا الشكل:

```text
المشكلة:

الجهاز المتأثر:
الخدمة المتأثرة:
الدليل:
مستوى الخطورة:
التأثير:
التوصية:
```

هذا يجعل التقرير أوضح وأسهل للمتابعة والمعالجة.
